# Telegram LLM Bot

Асинхронный Telegram-бот на Python 3.11+ и aiogram 3. Он предоставляет доступ к языковой модели через OpenAI-совместимый API, хранит историю в SQLite и при настройке [audiodoc](https://github.com/WhlteAdmln/audiodoc) обрабатывает аудио и извлекает текст из документов. Изображения, GIF, анимированные стикеры и видео обрабатываются локально.

Карта модулей и поток обработки описаны в [`docs/architecture.ru.md`](docs/architecture.ru.md). Англоязычная документация: [`README.md`](README.md) и [`docs/architecture.md`](docs/architecture.md).

## Требования

- Python 3.11 или новее.
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather).
- Запущенный LLM-сервер с `POST /v1/chat/completions` и поддержкой потоковой генерации.
- Необязательный сервис [audiodoc](https://github.com/WhlteAdmln/audiodoc) для распознавания аудио и извлечения текста из документов. Имена настроек `WHISPER_*` и `DOCUMENT_*` исторические: обе группы подключаются к audiodoc.
- `ffmpeg` и `ffprobe` в `PATH` для обработки видео и видео-стикеров.

## Установка

### Быстрая установка в Linux

В проекте есть установочный скрипт. Он скачивает опубликованный GitHub Release, проверяет системные инструменты, создаёт виртуальное окружение Python, устанавливает закреплённые зависимости и подготавливает конфигурацию. Каталог установки по умолчанию — `~/bot-obormot`.

Установка последнего стабильного релиза:

```bash
curl -fsSL https://raw.githubusercontent.com/WhlteAdmln/bot-obormot/main/install.sh | sh -s -- --latest
```

Установка последнего опубликованного prerelease (самого нового релиза GitHub с признаком prerelease):

```bash
curl -fsSL https://raw.githubusercontent.com/WhlteAdmln/bot-obormot/main/install.sh | sh -s -- --nightly
```

Добавьте `--systemd`, чтобы создать пользовательский systemd-юнит в `~/.config/systemd/user/bot-obormot.service`:

```bash
curl -fsSL https://raw.githubusercontent.com/WhlteAdmln/bot-obormot/main/install.sh | sh -s -- --latest --systemd
# или
curl -fsSL https://raw.githubusercontent.com/WhlteAdmln/bot-obormot/main/install.sh | sh -s -- --nightly --systemd
```

Установщик нужно запускать от обычного пользователя, не от `root`. `sudo` используется только при необходимости установить системные пакеты. Поддерживаются менеджеры пакетов APT, DNF/YUM, Pacman, Zypper и APK. Скрипт проверяет Python 3.11+, `pip`/`venv`, `unzip`, `curl`, инструменты сборки C/C++, CMake и FFmpeg. Если в репозиториях дистрибутива доступна только версия Python ниже 3.11, сначала установите Python 3.11 или новее. Установка FFmpeg выполняется по возможности; без `ffmpeg`/`ffprobe` обработка видео работать не будет.

Установщик создаёт `~/bot-obormot`, переименовывает `.env.example` в `.env`, ограничивает права `.env`, создаёт `.venv` и устанавливает пакеты из `requirements-lock.txt`. Существующий каталог установки не перезаписывается. Перед повторной установкой переместите или сохраните существующий каталог.

После установки откройте конфигурацию и обязательно задайте `BOT_TOKEN` и `SUPERVISOR_ID`:

```bash
nano ~/bot-obormot/.env
```

При использовании `--systemd` установщик создаёт юнит и обновляет конфигурацию systemd, но намеренно не включает и не запускает службу до настройки `.env`. После редактирования `.env` выполните:

```bash
systemctl --user enable --now bot-obormot.service
systemctl --user status bot-obormot.service
journalctl --user -u bot-obormot.service -f
```

Чтобы пользовательская служба запускалась при старте системы без интерактивного входа пользователя, администратор может включить lingering для учётной записи:

```bash
sudo loginctl enable-linger "$USER"
```

Дополнительные переменные установщика:

- `BOT_INSTALL_DIR` — другой каталог установки.
- `BOT_GITHUB_REPOSITORY` — переопределение GitHub-репозитория (по умолчанию `WhlteAdmln/bot-obormot`).
- `GITHUB_TOKEN` — токен GitHub, если требуется обход ограничений API или доступ к приватному репозиторию. Храните токен в секрете и не записывайте его непосредственно в историю команд.

Более безопасная альтернатива `curl | sh` — сначала скачать и просмотреть установщик:

```bash
curl -fsSLo install.sh https://raw.githubusercontent.com/WhlteAdmln/bot-obormot/main/install.sh
less install.sh
sh install.sh --latest
```

### Ручная установка

При ручной установке команды выполняются из корня проекта — каталога, в котором находятся `requirements.txt`, `bot/` и `prompts/`.

```bash
python3 -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate

python -m pip install -r requirements-lock.txt
cp .env.example .env
```

Откройте `.env` и обязательно заполните:

- `BOT_TOKEN` — токен, полученный у @BotFather;
- `SUPERVISOR_ID` — числовой Telegram ID главного администратора.

Замените примеры в `.env.example`: это шаблонные значения, а не рабочие учётные данные. Приложение загружает `.env` только из корня проекта (`PROJECT_ROOT/.env`), не выполняя поиск в родительских каталогах. Формат токена проверяется до создания объекта Telegram Bot.

Храните `.env`, API-ключи, SQLite-базу и пользовательские данные в закрытом доступе. Не добавляйте их в git и не публикуйте. В Linux/macOS ограничьте права уже существующего `.env` командой `chmod 600 .env`; при запуске приложение устанавливает `umask 0o077` для файлов и каталогов, которые создаёт сам процесс.

## Конфигурация

Все настройки необязательны, кроме `BOT_TOKEN` и `SUPERVISOR_ID`. Значения по умолчанию соответствуют `bot/config/settings.py` и `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---:|---|
| `BOT_TOKEN` | — | Обязательный токен Telegram-бота. Проверяется формат числового ID и секретной части. |
| `SUPERVISOR_ID` | — | Обязательный положительный числовой Telegram ID главного администратора. |
| `ADMIN_IDS` | пусто | Начальный список администраторов через запятую; переносится в SQLite одноразовой миграцией. |
| `ALLOWED_USERS` | пусто | Статический allowlist через запятую. При пустом списке доступ есть только у Supervisor и администраторов из БД, если не включён `ALLOW_ALL_USERS`. |
| `ALLOW_ALL_USERS` | `false` | При `true` открывает бота всем незаблокированным пользователям. Включайте только осознанно. |
| `LOG_LEVEL` | `INFO` | Уровни: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
| `DATABASE_PATH` | `data/bot.db` | Путь к SQLite. Каталог изображений `images/` создаётся рядом с файлом БД. |
| `LLM_BASE_URL` | `http://127.0.0.1:8080/v1` | Базовый URL OpenAI-совместимого API LLM-сервера (включая префикс `/v1`). |
| `LLM_API_KEY` | `not-needed` | Необязательный Bearer-токен LLM-сервера; при пустом значении или `not-needed` заголовок авторизации не отправляется. |
| `LLM_MODEL` | `local-model` | Имя модели, передаваемое серверу. |
| `LLM_TEMPERATURE` | `0.7` | Температура генерации; не может быть отрицательной. |
| `LLM_TOP_P` | `0.9` | Параметр семплирования от 0 до 1. |
| `LLM_MAX_TOKENS` | `2048` | Максимальное число генерируемых токенов. |
| `LLM_TIMEOUT` | `300` | Тайм-аут запроса LLM в секундах. |
| `LLM_CONTEXT_SIZE` | пусто | Размер контекстного окна в токенах. Задайте явно, если сервер не сообщает пригодные метаданные; стандартный OpenAI API не определяет поле длины контекста. |
| `LLM_TOKEN_COUNTING` | `auto` | Режим подсчёта токенов: `auto` один раз проверяет расширение llama.cpp `/tokenize` и при его отсутствии переходит к оценке; `llamacpp` требует эндпоинты токенизации llama.cpp; `estimate` не обращается к ним. |
| `LLM_MAX_CONCURRENT_GENERATIONS` | `1` | Максимальное число одновременных генераций LLM. |
| `MAX_HISTORY_EXCHANGES` | `1000` | Максимальный лимит истории, который администратор может назначить пользователю. Стандартный лимит обычного пользователя — 30 обменов. |
| `MAX_STORED_EXCHANGES` | `2000` | Максимальное число сохраняемых полных обменов на пользователя (до 4 000 строк сообщений). Старые записи и принадлежащие боту изображения удаляются после успешного ответа. |
| `WHISPER_API_URL` | пусто | Необязательный адрес распознавания audiodoc. Укажите полный URL вместе с `/transcribe`; при отсутствии адреса обработка аудио недоступна. |
| `WHISPER_API_KEY` | пусто | Необязательный Bearer-токен для распознавания в audiodoc. |
| `WHISPER_TIMEOUT` | `180` | Тайм-аут Whisper в секундах. |
| `DOCUMENT_API_URL` | пусто | Необязательный адрес обработки документов audiodoc. Укажите полный URL вместе с `/process-document`; при отсутствии адреса обработка документов недоступна. |
| `DOCUMENT_API_KEY` | пусто | Необязательный Bearer-токен для обработки документов в audiodoc. |
| `DOCUMENT_TIMEOUT` | `300` | Тайм-аут Document Engine в секундах. |

Важные ограничения заданы константами в коде, а не переменными окружения:

- `DEFAULT_HISTORY_EXCHANGES = 30` — стандартный лимит истории обычного пользователя.
- `MAX_CONTEXT_EXCHANGES = 100` — жёсткий предел числа обменов, загружаемых для одного запроса LLM, независимо от большего пользовательского лимита.
- `MAX_INPUT_TEXT_LENGTH = 12 288` символов — итоговый лимит длины входного текста.
- Входящие медиафайлы Telegram: не более 20 МиБ на файл и не более 3 одновременных скачиваний.
- `MAX_AUDIO_DURATION = 300` секунд (5 минут) для входящего аудио; константа определена в `bot/services/audio/validation.py`.

`MAX_HISTORY_EXCHANGES`, `MAX_CONTEXT_EXCHANGES` и `MAX_STORED_EXCHANGES` решают разные задачи: пользовательский лимит истории, предел контекста одного запроса и предел долговременного хранения соответственно.

### Совместимость с LLM-серверами

| Возможности сервера | Настройка и поведение |
|---|---|
| llama.cpp server | Полная совместимость. В режиме `auto` бот обнаруживает `/tokenize` и использует точный подсчёт токенов; `/props` может сообщить размер контекста. |
| Другие OpenAI-совместимые серверы | Используйте `LLM_TOKEN_COUNTING=estimate` (или `auto`: он перейдёт к оценке, если `/tokenize` недоступен) и задайте `LLM_CONTEXT_SIZE` равным реальному контексту модели. Метаданные `/v1/models` проверяются по возможности, но стандарт OpenAI API не определяет поле размера контекста. |
| Минимальный API чата | `POST /v1/chat/completions` с `stream=true`. Для команды `/health` бот сначала проверяет `/health`, а затем использует `GET /v1/models`. |

Не устанавливайте `LLM_TOKEN_COUNTING=llamacpp` для сервера, который не реализует расширения llama.cpp `/tokenize` и `/apply-template`. Оценка количества токенов приблизительна; в этом режиме бот использует увеличенный запас контекста.

Поддерживаемые форматы документов определяет audiodoc. Актуальный список приведён в [README audiodoc](https://github.com/WhlteAdmln/audiodoc).

## Запуск

```bash
python -m bot.main
```

Порядок запуска: установка ограничительной `umask`, настройка логирования и фильтрации секретов, настройка лимитов Pillow, проверка и запись режима доступа в лог, проверка формата Telegram-токена, подключение SQLite и применение миграций, запуск LLM-клиента, запуск периодической очистки изображений и переход к Telegram polling. При завершении останавливается фоновая очистка и закрываются LLM-клиент, соединение с БД и Telegram-сессия.

Бот рассчитан на личные чаты. Сообщения из групп, супергрупп и каналов, а также события без известного отправителя не передаются в чат-обработчики: история и персональные промпты привязаны к пользователю, а не к чату.

## Проверка LLM-сервера

```bash
curl http://127.0.0.1:8080/v1/models
```

Измените `LLM_BASE_URL`, если сервер использует другой адрес или порт. Если на LLM-сервере включена авторизация, задайте соответствующий секрет в `LLM_API_KEY`. Предпочтительно привязывать сервер к localhost или доверенному частному интерфейсу; не открывайте его напрямую в публичный интернет.

## Команды Telegram

### Доступны пользователям

| Команда | Назначение |
|---|---|
| `/start` | Показать справку и настроить меню команд пользователя. |
| `/history` | Показать текущий персональный лимит истории. |
| `/history_limit N` | Установить собственный лимит истории. Для обычных пользователей действует стандартный максимум; администраторы могут использовать `MAX_HISTORY_EXCHANGES`. |
| `/history_clear` | Удалить историю диалога и принадлежащие боту изображения. |
| `/forget_me` | Удалить историю, принадлежащие боту изображения, персональный системный промпт и индивидуальный лимит истории. Команда не отзывает доступ и не меняет списки администраторов/блокировок. |
| `/prompt` | Показать действующий системный промпт. |
| `/prompt_set` | Начать установку персонального системного промпта. |
| `/prompt_reset` | Удалить персональный промпт и вернуться к стандартному. |
| `/cancel` | Отменить ввод промпта, если активно соответствующее FSM-состояние. |

### Доступны администраторам и Supervisor

| Команда | Назначение |
|---|---|
| `/health` | Проверить доступность Telegram API, SQLite и LLM. |
| `/history_limit USER_ID N` | Назначить лимит истории другому пользователю. |
| `/ban USER_ID` | Немедленно заблокировать обычного пользователя. |
| `/unban USER_ID` | Снять блокировку пользователя. |

### Только Supervisor

| Команда | Назначение |
|---|---|
| `/admin` | Показать панель администрирования. |
| `/admins` | Показать список администраторов из БД. |
| `/admin_add USER_ID` | Добавить администратора в SQLite. |
| `/admin_remove USER_ID` | Удалить администратора из SQLite. |

Администратор не может заблокировать Supervisor или другого администратора. Перед блокировкой администратора сначала удалите его права командой `/admin_remove`. Supervisor заблокировать нельзя. Управление администраторами, блокировки/разблокировки, изменение чужого лимита истории и отказы при вызове административных обработчиков фиксируются в логах записями `AUDIT`.

## Тесты

Установите закреплённые runtime-зависимости и инструменты разработки:

```bash
python -m pip install -r requirements-dev.txt
```

Запуск обычного набора тестов:

```bash
python -m pytest -q
```

Интеграционный тест с маркером `integration`, которому нужен внешний LLM-сервер с эндпоинтом `/tokenize`, запускается отдельно:

```bash
python -m pytest -m integration -q
```

По умолчанию `pytest.ini` исключает интеграционные тесты, поэтому обычный набор не требует внешней LLM.

## Базовые меры безопасности

В приложение включены следующие меры укрепления безопасности:

- **Контроль доступа:** закрытый режим по умолчанию; только личные чаты; события без отправителя отбрасываются; блокировки из SQLite проверяются для пользователей, кроме Supervisor; уведомления об отказе ограничены по частоте. `ALLOW_ALL_USERS=true` — явное включение открытого доступа.
- **Защита от перегрузки:** 10 входящих событий на пользователя за 10 секунд, не более 3 ожидающих/выполняющихся запросов чата на пользователя, скачивание файлов до 20 МиБ, не более 3 одновременных скачиваний и ограниченная параллельная обработка изображений/анимаций.
- **Недоверенные медиафайлы:** тип определяется по содержимому; настроены лимиты Pillow, GIF/TGS/видео по размеру холста, кадрам и длительности; для `ffmpeg`/`ffprobe` заданы тайм-ауты, доступ только к локальным файлам и ограничения ресурсов subprocess.
- **Внешние HTTP-сервисы:** ответы Whisper и Document Engine читаются потоком с лимитом 2 МиБ для успешного тела и лимитом чтения тела HTTP-ошибки 2 КиБ. Поддерживаются необязательные Bearer-ключи. Для удалённых сервисов используйте HTTPS.
- **Вход LLM:** известные служебные маркеры шаблонов нейтрализуются во всех несистемных сообщениях; в стандартном промпте указано, что текст документов, расшифровки и подписи — это данные, а не команды. Это эшелонированная защита, а не гарантия устранения всех вариантов prompt injection.
- **Секреты и логи:** фильтр маскирует токены Telegram и API-ключи; текст расшифровок не записывается; имена файлов, MIME-метаданные и детали ошибок очищаются перед логированием; действия администраторов фиксируются записями `AUDIT`.
- **Локальные данные:** при запуске задаётся `umask 0o077` в Unix-подобных системах; `.env` читается только из корня проекта; формат Telegram-токена проверяется; удалять разрешено только управляемые файлы с UUID-именами внутри настроенного каталога изображений.
- **Хранение данных:** на пользователя хранится не более `MAX_STORED_EXCHANGES` полных обменов; вместе со старыми сообщениями очищаются принадлежащие боту изображения. Ежедневная задача удаляет медиа старше 30 дней и осиротевшие управляемые файлы после защитного периода 24 часа.

Для production устанавливайте точные версии из `requirements-lock.txt`. В `requirements.txt` заданы допустимые диапазоны версий для гибкой установки. Не реже одного раза в месяц проверяйте lock-файл на известные уязвимости:

```bash
python -m pip install pip-audit
pip-audit -r requirements-lock.txt
```

Изучайте каждую найденную проблему, осознанно обновляйте затронутые зависимости и запускайте полный набор тестов до развёртывания. `pip-audit` сообщает об известных уязвимостях, но не доказывает полную безопасность приложения или зависимостей.

`umask` не меняет права уже существующих файлов. Для существующих данных в Linux/macOS проверьте и ограничьте права, например:

```bash
chmod -R go-rwx data
chmod 600 .env
```

Не публикуйте `.env`, Telegram-токены, API-ключи, пользовательскую базу данных и логи с операционными данными. `SUPERVISOR_ID` должен указывать на доверенный аккаунт с полным административным контролем.
