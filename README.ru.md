# Telegram LLM Bot

Асинхронный Telegram-бот на Python 3.11+ и aiogram 3. Он хранит историю в SQLite, обращается к локальной LLM через OpenAI-compatible API `llama-server` и при настройке дополнительных сервисов обрабатывает аудио, документы, изображения и анимации.

## Требования

- Python 3.11 или новее.
- Telegram bot token от [@BotFather](https://t.me/BotFather).
- Доступный `llama-server` с OpenAI-compatible API.
- Дополнительные сервисы Whisper и Document Engine нужны только для соответствующих функций.

## Установка

Команды выполняются из каталога `telegram_bot` — там, где находятся `requirements.txt`, `bot/` и `prompts/`.

```bash
python3 -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate

python -m pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и обязательно заполните:

- `BOT_TOKEN` — токен, полученный у @BotFather;
- `SUPERVISOR_ID` — ваш числовой Telegram ID.

Остальные параметры можно оставить со значениями из примера и менять по необходимости. Файл `.env.example` содержит все поддерживаемые настройки окружения и безопасные шаблонные значения. Сам `.env` содержит локальные секреты и не должен передаваться другим пользователям или попадать в публикуемые архивы.

Узнать свой числовой Telegram ID можно через специального Telegram-бота, например @userinfobot. Перед запуском замените строку `REPLACE_WITH_NUMERIC_TELEGRAM_ID` на число.

## Конфигурация

| Переменная | Обязательна | Значение по умолчанию / назначение |
|---|---:|---|
| `BOT_TOKEN` | Да | Токен Telegram-бота. |
| `SUPERVISOR_ID` | Да | Положительный числовой Telegram ID главного администратора. |
| `ADMIN_IDS` | Нет | Дополнительные администраторы через запятую; при первом запуске используются существующей миграцией SQLite. |
| `ALLOWED_USERS` | Нет | Разрешённые пользователи через запятую. Пустое значение открывает доступ всем; администраторы имеют доступ независимо от списка. |
| `LOG_LEVEL` | Нет | `INFO`; допустимые уровни: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
| `DATABASE_PATH` | Нет | `data/bot.db`; путь к SQLite. Каталог для файла создаётся приложением. |
| `LLM_BASE_URL` | Нет | `http://127.0.0.1:8080/v1`; базовый URL OpenAI-compatible API. |
| `LLM_API_KEY` | Нет | `not-needed`; значение для заголовка авторизации, если сервер его требует. |
| `LLM_MODEL` | Нет | `local-model`; имя модели, передаваемое серверу. |
| `LLM_TEMPERATURE` | Нет | `0.7`; температура генерации, не меньше нуля. |
| `LLM_TOP_P` | Нет | `0.9`; значение от 0 до 1. |
| `LLM_MAX_TOKENS` | Нет | `2048`; максимальное число генерируемых токенов. |
| `LLM_TIMEOUT` | Нет | `300`; тайм-аут запросов LLM в секундах. |
| `LLM_MAX_CONCURRENT_GENERATIONS` | Нет | `1`; максимальное число одновременных генераций. |
| `MAX_HISTORY_EXCHANGES` | Нет | `1000`; верхний предел пользовательского лимита истории. Стандартный лимит приложения — 30 полных обменов. |
| `WHISPER_API_URL` | Нет | Пусто; URL Whisper API. При пустом значении обработка аудио недоступна. |
| `WHISPER_TIMEOUT` | Нет | `180`; тайм-аут Whisper в секундах. |
| `DOCUMENT_API_URL` | Нет | Пусто; URL Document Engine. При пустом значении обработка документов недоступна. |
| `DOCUMENT_TIMEOUT` | Нет | `300`; тайм-аут Document Engine в секундах. |

Дополнительно: ограничение извлекаемого пользовательского текста задаётся в коде и сейчас составляет 12 288 символов. Параметр `STREAM_UPDATE_INTERVAL` всё ещё присутствует в объекте конфигурации для совместимости, но фактический интервал обновления потокового ответа сейчас задан в streaming-модуле и равен 0,8 секунды; переменная окружения на него не влияет.

## Запуск

Из корня проекта:

```bash
python -m bot.main
```

Порядок запуска приложения: подключение SQLite, запуск LLM-клиента, запуск фоновой очистки изображений, затем Telegram polling. При завершении приложение останавливает фоновую задачу и закрывает LLM, SQLite и Telegram-сессию.

## Проверка `llama-server`

```bash
curl http://127.0.0.1:8080/v1/models
```

Если сервер использует другой адрес или порт, измените `LLM_BASE_URL` в `.env`. Если сервер требует определённое имя модели, укажите его в `LLM_MODEL`.

## Команды бота

- `/start` — справка и доступные команды.
- `/history` — текущий лимит истории.
- `/history_limit` — изменить лимит истории.
- `/history_clear` — очистить историю диалога.
- `/prompt` — показать системный промпт.
- `/prompt_set` — начать установку системного промпта.
- `/prompt_reset` — сбросить пользовательский системный промпт.
- `/cancel` — отменить ввод промпта в соответствующем FSM-состоянии.
- `/health` — состояние внешних компонентов (административная команда).
- `/admin`, `/admins`, `/admin_add`, `/admin_remove` — управление администраторами.

## Тесты

Установите зависимости для разработки:

```bash
python -m pip install -r requirements-dev.txt
```

Обычный набор тестов:

```bash
python -m pytest -q
```

Интеграционные тесты, требующие работающего `llama-server`, запускаются отдельно:

```bash
python -m pytest -m integration -q
```

По умолчанию `pytest.ini` исключает тесты с маркером `integration`, поэтому обычный запуск не зависит от доступности внешней LLM.

## Структура проекта

Подробная карта модулей и их ответственности находится в [`docs/architecture.md`](docs/architecture.md).

Системный промпт загружается при импорте конфигурации из `prompts/systemPrompt.md`; файл должен присутствовать. История и связанные с ней файлы изображений хранятся локально рядом с SQLite-базой. Фоновая очистка запускается раз в сутки; текущие параметры — 30 дней хранения ссылок на старые изображения и 24 часа защитного периода для осиротевших файлов.

## Безопасность

- Не публикуйте `.env`, токен Telegram, API-ключи и пользовательскую SQLite-базу.
- Не передавайте секреты в issue, логи или архивы с исходным кодом.
- Не открывайте порт `llama-server` в интернет без отдельной аутентификации и сетевой защиты.
- `SUPERVISOR_ID` должен указывать на доверенный аккаунт: он получает полный административный контроль над ботом.
